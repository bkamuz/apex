# UI internationalization (i18n)

Apex ships a lightweight message-catalog layer for the web UI. **English** and
**Russian** are built in. The preference is stored in `localStorage` under
`apex.locale` and survives reloads.

## Switching language

Use the **Language** select in the top bar (next to Kernel), or from the
console / a plugin:

```js
window.apex.i18n.setLocale('ru')  // or 'en'
window.apex.i18n.getLocale()
```

Default locale is `en` (smoke tests and English UI remain the baseline).

## Catalogs

| Path | Role |
|------|------|
| `apps/web/src/i18n/catalogs/en.ts` | Source-of-truth keys + English strings |
| `apps/web/src/i18n/catalogs/ru.ts` | Russian translations (same keys) |
| `apps/web/src/i18n/t.ts` | `t(key, params?, fallback?)`, locale persistence |
| `apps/web/src/i18n/display.ts` | Tool / tab / component / exporter label helpers |
| `apps/web/src/i18n/I18nProvider.tsx` | React context (`useI18n`) |

Templates use `{name}` placeholders:

```ts
t('placement.moreClicks', { name: 'Wall', n: 2, s: 's', elev: '' })
```

Lookup order: active locale → English catalog → `fallback` argument → raw key.

## How tools and plugins should take translated strings

### Preferred: call `t` in `hint()` (and any live status / errors)

```ts
import { t } from '../i18n';
// or: window.apex.i18n.t

hint(pendingCount) {
  return t('tool.acme.hello.hint');
},
onClick(_e, ctx) {
  ctx.setError(t('tool.acme.hello.error'));
},
```

`hint()` runs on every render of the status line, so locale switches update live
without re-registering the tool.

### Toolbar labels

Keep a stable English `label` on the `Tool` (fallback + descriptors). The
toolbar resolves display text as:

1. `component.<id>` when the tool id is `place:<componentId>`
2. else `tool.<toolId>.label`
3. else `tool.label`

Add matching keys to `en.ts` / `ru.ts` for first-party tools. Third-party tools
can either contribute keys (PR to catalogs) or pass a translated string as
`label` and accept that it will not switch until re-registered.

### Tabs

Catalog tabs (`ApexTabs.*`) are translated via `tab.<id>` (e.g.
`tab.apex.building`). Open-world custom tabs fall back to the author's `label`.

### Draw modes / exporters

- Modes: `mode.<id>` (`line`, `arc`, `polyline`, …)
- Exporters: `exporter.<id>.label` / `exporter.<id>.title`

### React chrome

Use `const { t } = useI18n()` inside components under `I18nProvider` (already
wrapped in `main.tsx`).

## Adding a locale

1. Add the id to `Locale` / `LOCALES` / `LOCALE_LABELS` in `types.ts`.
2. Add `catalogs/<id>.ts` and register it in `catalogs/index.ts`.
3. Translate every key from `en.ts` (missing keys fall back to English).

## Out of scope (still English)

- Core / WASM error messages from Rust
- Component **parameter** labels from `ParamSpec` / profiles (data-driven English)
- Deep editor UIs (Component editor, Profile sketch editor, genus prompts)
- Sheet layout control microcopy, some view-export button labels
- Agent bridge panel body copy beyond aria/title
- User-authored component / type display names
